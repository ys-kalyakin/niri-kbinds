# Design

## Context

Пользовательские строки размазаны по коду без единого механизма: оверлей (`src/ui/app.rs`), диагностика (`src/lib.rs`, `src/exec.rs`, `src/fuzzel.rs`, `src/ui/app.rs`), находки аудита (`src/audit.rs`), CLI help (`src/main.rs`, clap derive doc-comments) и крупнейший пласт — словарь дефолтных заголовков/групп (`src/groups.rs`, ~84 экшена + 7 групп, приставочные правила и «Прочее»). Проект минимизирует зависимости (см. пиннинг winit в `Cargo.toml`). Язык процесса в Wayland-сессии задаётся стандартными переменными локали.

## Goals / Non-Goals

**Goals:**
- Выбор языка по системной локали для всех пользовательских строк, без новых крейтов.
- Компилируемая гарантия полноты каталога (оба языка в одной записи).
- Детерминированные тесты: язык передаётся явно, без манипуляции env в тестах.

**Non-Goals:**
- Живое переключение языка в работающем процессе; локаль фиксируется на старте.
- Локализация данных из конфига пользователя и комментариев/документации.
- Локализация JSON-имён полей, `id`, промпта fuzzel, имён экшенов `niri`.
- Новые языки помимо `ru`/`en` (добавление нового языка должно сводиться к одной новой записи на сообщение).

## Decisions

### D1. Собственный статический каталог, без крейтов
`src/l10n.rs` с `pub enum Lang { En, Ru }`. Один модуль-каталог; сообщения — записи «ключ + перевод на оба языка». Альтернативы: `fluent-rs` (рантайм FTL, избыточно для 2 языков), `rust-i18n` (кодогенерация, внешняя зависимость) — отклонены: объём мал, проект держит дерево зависимостей минимальным.

### D2. Перечисление сообщений + `tr(Msg)`, параметризованные — функциями
Простые строки: `pub enum Msg { SearchPlaceholder, FooterHints, … }`, `pub fn tr(lang: Lang, msg: Msg) -> &'static str` — один `match`, отсутствие перевода в любой из локаелей не компилируется. Строки с подстановками (счётчик «{visible} из {total}», диагностика с путями/id) — типизированные функции в `l10n` (`pub fn counter(lang, visible, total) -> String` и т.п.), т.к. динамические аргументы `format!` в Rust требуют литеральной строки формата. Альтернатива (строковые ключи + `HashMap`) отклонена: опечатка ключа ловится только в рантайме; enum даёт это на компиляции.

### D3. Язык: глобальный `OnceLock<Lang>` для UI/CLI, явный `Lang` в аргументах для ядра
`l10n::init()` в начале `main()` (и в `src/bin/overlay.rs`, если это отдельная точка входа) читает `LC_ALL` → `LC_MESSAGES` → `LANG`, парсит подтег до `_`/`-`/`.`, `C`/`POSIX`/пусто/неизвестно → `En`. Функции ядра, порождающие строки (`groups.rs` резолюция title/group, формирование находок `audit.rs`), принимают `Lang` параметром; UI и CLI читают глобальный. Причина: `env::set_var` в тестах гонок и `unsafe` в новых редакциях — тесты вызывают ядро с явным `Lang::Ru`/`Lang::En`.

### D4. Словарь `groups.rs`: ключ группы + пара заголовков
`ACTION_TITLES` → `&[(&str action, Group, &str title_en, &str title_ru)]`, где `enum Group { Windows, Workspaces, Navigation, Screenshots, System, Apps, Other }`; `group_by_prefix`/`spawn_group` возвращают `Group`; `group_name(Group, Lang) -> &'static str` локализует при выводе. `Bind.group` остаётся `String` — заполняется локализованным именем при построении модели (язык уже зафиксирован), поэтому JSON-схема, сортировка `cmd_list` по `group` и поиск по `search_text` (куда входят title/group) продолжают работать без изменений модели. Проверка «имя экшена есть в словаре» для A2 — по имени экшена, локаль не затрагивает.

### D5. CLI: сохранить derive, тексты накладывать билдером
В `main()`: `let mut cmd = Cli::command(); l10n::apply_cli_texts(&mut cmd, lang);` — переопределение `about` корневой команды, подкоманд и help аргументов через builder API (`find_subcommand_mut`, `mut_arg`), затем `cmd.get_matches()` + `Cli::from_arg_matches`. Альтернативы: полный переход на builder API (большой дифф без выигрыша), локализация внутри derive (не поддерживается) — отклонены. Doc-comments в `main.rs` становятся внутренней документацией; авторитетные тексты — в `l10n`.

### D6. Diagnostics и audit находки через `tr`/функции
Все `.context(...)`/`bail!`/`eprintln!` с человекочитаемым текстом заменяются на вызовы `l10n` (формат подстановок — типизированные функции). Находки аудита собирают сообщения в момент формирования с явным `Lang`; `--json` пишет тот же текст сообщения (значение поля, не имя).

## Risks / Trade-offs

- [Значения `title`/`group` дефолтных биндов в `list --json` зависят от локали] → задокументировано в proposal как мягкий BREAKING; поля/`id`/коды выходов стабильны; пользовательские значения не меняются. Потребители, которым нужен стабильный заголовок, могут опираться на `overlay_title` или `id`.
- [Порядок групп в `list`/оверлее определяется сортировкой по локализованному имени] → внутри локали порядок стабилен; между локалями может отличаться — приемлемо для человекочитаемого вывода (спека требует стабильности внутри запуска, не между локалями).
- [~120 переводов — риск смысловых ошибок в en] → приёмка прогоном с `LANG=ru_RU.UTF-8` и `LC_ALL=en_US.UTF-8` по чек-листу поверхностей; полнота гарантируется компиляцией.
- [Тесты, закрепляющие русские дефолты (`items.rs`, `parser.rs`, `audit.rs`, интеграционные)] → перепроверить и явно фиксировать `Lang` в вызовах; env в тестах не трогать.
- [Переопределение clap-текстов расходится с doc-comments] → doc-comments привести к коротким внутренним описаниям, чтобы не было двух «истин».

## Migration Plan

Один бинарник, данных и конфигов миграция не требует. Откат — revert коммита. После внедрения: `cargo test`, затем ручная приёмка `--help`, `list`, `audit`, `dmenu`, `overlay` при двух локалях.

## Open Questions

Нет — решения покрывают все поверхности; добавление языков позже не меняет подход.
