- [x] 2.2 `parser.rs`: разбор узлов блока `binds { … }` крейтом `kdl` в режиме v1 (design D1), `include` с резолюцией относительно включающего файла, сплайсинг верхнеуровневых узлов, защита от циклов (ошибка парсинга с именем файла), сохранение `file`/`line`, накопление неизвестных свойств в `raw`, толерантность к `XF86*`/`condition`. - [x] 2.3 `normalize.rs`: канонизация `combo` (порядок модификаторов mod, ctrl, shift, alt; клавиша lowercase), `keys_display` (`Return`→`Enter`, `Left/Right/Up/Down`→`←/→/↑/↓`, `Slash`→`/`), кириллическая таблица — 24 имени из §7.2 ТЗ, снятые с `/usr/include/X11/keysymdef.h` (design D3), зафиксированные `const`; неизвестное имя — сырое без ошибки; `keys_raw` сохраняет оригинал. Проверка: юнит-тест на каждую из 24 пар кириллицы + тесты спецклавиш + тест канонизации.
- [x] 2.4 Фикстуры `tests/fixtures/`: `edge.kdl` (все случаи §7.1 ТЗ: кириллица — все 24 имени, блок-форма, spawn-sh, `repeat=false`, дублированный combo, комментарии, include обычный, неизвестные свойства, `XF86*`), `edge-inc.kdl` (цель include), `cycle-a.kdl`+`cycle-b.kdl` (цикл), `conflict.kdl` (минимальный конфликт A1), `clean.kdl` (без находок). Проверка: юнит-тесты — детерминированность групп между запусками, приоритет заголовка, fallback для неизвестного экшена.

## 3. CLI: list и exec (M2)

- [x] 3.1 Команда `list`: текстовый вывод (одна строка на бинд — design D9) и `--json` (`serde_json::to_string_pretty`, схема §6). Проверка: на живом конфиге `kbinds list --json | jq '.[] | select(.group=="Воркспейсы")'` возвращает только воркспейс-бинды; JSON валиден; у всех биндов заполнены `combo`, `keys_display`, `group`, `search`.
- [x] 3.2 `exec.rs`: маршрутизация `builtin` → `niri msg action <имя> <аргументы…>`, `spawn` → `niri msg action spawn -- <argv…>`, `spawn-sh` → `niri msg action spawn-sh -- "<строка>"` (design D2); несколько действий по порядку; поиск по `id`, неизвестный id → код 2. Проверка: юнит-тесты построения argv для трёх видов действий и порядка; живой запуск на заведомо безопасном builtin.
- [x] 3.3 Флаг `--dry-run`: печать итоговых команд в stdout без выполнения, код 0. Проверка: `kbinds exec mod-t --dry-run` печатает корректную команду и ничего не выполняет (приёмка §15.4).
- [x] 3.4 Коды выхода и диагностика: ошибка IO/парсинга/usage/неизвестный id → код 2, сообщение в stderr, stdout пуст (design D7). Проверка: запуск с несуществующим `--config` и `exec no-such-id` дают код 2 и пустой stdout.

- [x] 5.5 Вывод аудита: человекочитаемый на русском, `--json` (id правила, уровень, сообщение, ссылки на бинды), `--strict` → код 1 при наличии error-находок, без находок → код 0.
